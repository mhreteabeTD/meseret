1. **Never skip a step** in worked examples or explanations. Show LCM conversions as (top × k)/(bottom × k) and say why k; every simplification with the common factor; every mixed → improper change as (whole × denominator + numerator)/denominator; every regrouping/borrowing step in column arithmetic. ## What is new for Grade 5: the book is in Amharic
Decisions made (build them, don't ask again):
- **Lesson language follows the book.** Grade 5 lesson text, questions, options, clues, explanations and worked steps are in **Amharic**, faithful to the book's wording. The app UI language stays whatever the student chose.
- **Key words** carry the Amharic term as the main word and the English term as a gloss (the reverse of Grades 7+), because students switch to English-medium maths in Grade 7. Schema: keep `en` filled with the English term and add `"main": "am"` on the lesson so the player shows Amharic first. If the player can't do this yet, that is an engine change: add it, then use it.
- **Every lesson gets `"lang": "am"`.** The player must then use Amharic for the fixed words inside lessons: "Quick check", "Think first", "Worked example", "Check", "Next step", the answer pop-ups, the number-line prompts and the Practise labels, regardless of the UI language. Add these to `app/i18n/am.json` (most exist) and pick them by lesson language, not UI language.
- **Generators need Amharic text.** Give each generator a language parameter and write the Amharic sentence templates (same numbers and maths, Amharic words). Ethiopian numerals are not used in school maths; keep Arabic digits. Decimal point stays ".".
- **Typed answers:** `num` blanks already accept numbers in any form. For word answers in Amharic, the `a` list must hold the accepted spellings (common variants: ሀ/ሐ/ኀ, ሰ/ሠ, አ/ዐ, ጸ/ፀ; the player's 1–2 letter tolerance helps but list the main variants).
- **Text size:** Amharic needs ~10% larger type and more line height; the CSS does this through `[lang]`. Put `lang="am"` on lesson blocks of an Amharic lesson.
- **Translation tool:** select-to-translate should translate Amharic → English for these lessons (reverse direction). Make the direction follow the lesson language.
- **Machine Amharic** is not needed for the book's own text (it is original Amharic). Anything Claude writes in Amharic (hooks, clues, added practise, generator templates) is marked `"machine": true` for a speaker to check.
- **Grade 5 level:** shorter sentences (under 12 words), more pictures, more counting/visual models (fraction bars, number lines, place-value charts, arrays), fewer symbols. Expect topics like whole numbers to millions, place value, the four operations, fractions and decimals, measurement, geometry and data. Add new blocks only where the existing ones can't show the idea (e.g. a place-value chart or a column-arithmetic block with carrying); propose each new block in one line, then build it.

## The new engine feature: "Ask Meseret" (context-aware help chat)
Decisions made:
- **What:** a "🙋 Ask Meseret" button on every question card and section heading, plus one floating button on the book page. It opens a chat panel (bottom sheet) that already knows: chapter, section, the read text around the student, the current question, the student's answers and tries, the lesson language and the UI language.
- **How it teaches:** Socratic. Hints and guiding questions first, never the answer to a graded question before the student has tried twice (same rule as the player). It explains in the student's language (Amharic or English). It stays on the lesson and the subject and politely refuses anything else. One-tap chips: "Explain this step", "Give me a hint", "Show another example" (the last uses `Gen` locally: free and instant).
- **Architecture:** the PWA never holds an API key. A small **Cloudflare Worker** (`server/ask-worker.js`, free tier) receives `{lesson, section, context, question, history, lang}`, builds the system prompt (teaching rules + context), calls the **Anthropic Messages API with a Claude Haiku model** (check the current model id in the docs), streams the reply back. Keep the context small: only the current section's text and the current question, not the whole chapter.
- **Limits:** 15 messages per student per day, counted in the Worker by an anonymous device id; the panel shows how many are left. Free chapters include the chat with this limit (it is a selling point for the pilot schools); paid plans can raise it later.
- **Safety (students are minors):** no names, emails or phone numbers sent; the Worker strips them. Conversations are logged (no personal data) for teacher review; a 🚩 report button on every reply. A short refusal for off-topic or unsafe requests. Rate-limit and size-limit requests in the Worker.
- **Offline / weak data:** text only, streamed; if offline the button says so and offers "Show another example" (local).
- **What the owner must do (once):** create an Anthropic API key and a free Cloudflare account, run the deploy steps you write (or paste a Cloudflare API token so the cloud session can deploy). Write these steps for a tablet user, in one short list. Until the Worker exists, the chat button shows "coming soon" — build and ship the front end anyway, behind `ASK_URL` in `app.js`.
- **Events:** log `{lesson, section, item, asked, at}` with `logEvent` so we can see where students get confused. This is valuable product data.
